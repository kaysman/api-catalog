# api-catalog

Code-first OpenAPI catalog for Express, NestJS, and Rust. Write your routes once with inline documentation — the library generates the OpenAPI spec and serves an interactive Postman-style UI automatically.

Inspired by GoSwagger: the spec is a byproduct of your code, not a separate document you maintain in parallel.

---

## How it works

You annotate routes with documentation at the point where you define them. At startup, `api-catalog` assembles the OpenAPI 3.x document and mounts two endpoints:

- `GET /docs` — interactive UI (try-it console, schema browser, auth config)
- `GET /docs/default.json` — raw OpenAPI JSON (importable into Postman, Insomnia, etc.)

No code generation. No spec files to commit. No sync drift.

## UI development

The `ui/` directory is the single source of truth for the catalog frontend. Both the Node.js package and the Rust crate read from it.

**Rust** embeds `ui/styles.css` and `ui/client.js` directly at compile time via `include_str!` — no extra step needed.

**Node.js** uses TypeScript constant wrappers generated by a script. After editing `ui/`:

```sh
node scripts/build-ui.mjs
```

This regenerates `packages/node/src/ui/styles.ts` and `packages/node/src/ui/client.ts`.

## Development

```sh
# Type-check the Node.js package
npm run lint -w api-catalog

# Rebuild UI wrappers after editing ui/
npm run build:ui

# Type-check the Rust crate (requires Rust toolchain)
cargo check --manifest-path packages/rust/Cargo.toml
```
